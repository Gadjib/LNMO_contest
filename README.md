# ЛНМО Контест

Система олимпиадных задач для небольшого школьного сервера: Go, SQLite (WAL), Nginx и Isolate. Очередь хранится в базе, Redis и PostgreSQL не требуются. Один worker последовательно проверяет отправки на Python 3 и C++17.

## Работа с сайтом

1. Войти под администратором. Первоначальные данные доступа находятся в локальном `access.txt` (он исключён из Git).
2. В разделе «Ученики» создать аккаунты учеников и учителей. Обычный учитель может создавать только учеников; администратор — также учителей.
3. Создать контест, указать даты в московском времени и опубликовать его. До начала ученики видят карточку, но не задачи.
4. Добавить задачи через форму или ZIP. Формат и все ограничения описаны в [docs/task-format.md](docs/task-format.md), пример — в [examples/sum](examples/sum).
5. Ученик открывает задачу и отправляет исходный код либо файл. Результат обновляется автоматически.
6. Учитель видит общую таблицу контеста и историю решений каждого ученика. Повторная проверка выполняется на исходной версии тестов.

В разделе «Ученики» класс назначается при создании аккаунта или меняется нажатием на класс в строке ученика. Можно ввести новое название; регистр приводится к строчному, лишние пробелы удаляются. Пустое поле означает «Без класса».

Фильтр «Класс» доступен в списке учеников, отправках и результатах контеста. Используется текущий класс ученика: при переводе в другой класс его история решений отображается в новом классе. Существующие аккаунты при обновлении сохраняются без назначенного класса.

В настройках контеста можно выбрать «Все ученики» или «Только выбранные классы» и отметить один или несколько классов. Существующие контесты после обновления остаются доступны всем. Ограничение проверяется для списка контестов, прямых ссылок на контест и задачи, отправки решений и картинок. Учителя и администраторы видят все контесты. При переводе ученика в другой класс доступ меняется сразу; его прежние отправки остаются в личной истории. Таблица результатов ограниченного контеста включает выбранные классы и всех ранее сдававших его учеников, чтобы результаты не терялись.

Персональные назначения, интерактивные задачи, произвольные пользовательские чекеры и публичный рейтинг пока не предусмотрены. Для некоторых задач с неединственным ответом есть встроенные чекеры.

## Сходство решений

Проверяющий процесс автоматически сравнивает новые и ранее отправленные решения разных школьников для одной задачи и одного языка, включая разные классы и версии задачи. Собственные повторные попытки и решения учителей не сравниваются. Баллы и вердикты тестов не меняются.

При сходстве от 85% учитель видит отметку в списке отправок и предупреждение в карточке решения со ссылками на похожие отправки. Показывается по одному лучшему совпадению на ученика (до 20 учеников). Ученикам чужие решения и сведения о совпадениях недоступны.

Метод лексический: пробелы и комментарии пропускаются, имена пользовательских переменных и функций нормализуются. Строковые и числовые литералы сохраняются. Процент — коэффициент Дайса для мультимножеств последовательностей из пяти токенов. Для кода короче 20 токенов учитывается только полное совпадение токенов без переименования. Это эвристика, а не анализ семантики: перестройка алгоритма может скрыть сходство, а типовые короткие решения могут совпадать независимо. Отметка не доказывает списывание и не определяет, кто у кого заимствовал код.

Результаты сохраняются в SQLite; повторное открытие страницы не запускает пересчёт. После обновления worker постепенно обработает старые отправки. До завершения анализа отображается «Ожидает проверки».

## Локальная сборка

Нужен Go 1.26 или совместимый более новый выпуск. Зависимости закреплены в `go.mod` / `go.sum`.

```sh
make test
make vet
make build
```

Бинарный файл не требует CGO и включает HTML, CSS и JavaScript. Node.js для сборки и работы сайта не нужен.

```sh
read -rs CONTEST_PASSWORD
export CONTEST_PASSWORD
bin/contests init -db data/contests.db
unset CONTEST_PASSWORD
bin/contests serve -db data/contests.db -addr 127.0.0.1:8080
```

Команда `init` создаёт администратора `admin` и демонстрационный контест; при существующих пользователях отказывается повторять инициализацию. Веб-интерфейс работает без Isolate, но отправки останутся в очереди. Для проверки нужен Linux с рабочими namespaces, cgroup v2 и установленным Isolate.

## Установка на Debian 13

Системные пакеты:

```sh
apt-get update
apt-get install -y nginx python3 g++ gcc make git pkg-config \
  libcap-dev libseccomp-dev libsystemd-dev ca-certificates curl sqlite3
```

Песочница использует Isolate 2.7, проверенный commit `8f185bb37f3f23e29b33b0c7727c91c13429abe3`:

```sh
git clone https://github.com/ioi/isolate.git /opt/isolate-src
git -C /opt/isolate-src checkout 8f185bb37f3f23e29b33b0c7727c91c13429abe3
make -C /opt/isolate-src install
```

Скопировать `bin/` и `deploy/` из локального проекта в `/opt/contests/`, затем от root:

```sh
read -rs CONTEST_PASSWORD
export CONTEST_PASSWORD
bash /opt/contests/deploy/install.sh
unset CONTEST_PASSWORD
```

Скрипт создаёт системного пользователя `contests`, конфигурации Nginx и systemd, ограниченное tmpfs для песочницы, начальную базу и запускает службы. При обновлении существующая база сохраняется, пароль не требуется. Скрипт предназначен для выделенного сервера: он заменяет стандартный сайт Nginx, сохраняя его ссылку в `sites-available/contests-previous-default-link`.

UID/GID 60000 зарезервирован для песочницы 0; этот идентификатор не должен использоваться другими аккаунтами. Isolate принадлежит `root:contests` с режимом `4750`. Веб-служба запрещает повышение привилегий, worker использует setuid-Isolate. Сервер LXC должен разрешать namespaces и делегировать cgroup v2. Эти возможности проверяются командой `contests sandbox-check`; при отказе проверка решений не запускается.

## Размещение и службы

| Что | Где |
|---|---|
| Исполняемый файл | `/opt/contests/contests` |
| База, версии задач, тесты, решения и результаты | `/var/lib/contests/contests.db` |
| Веб-служба | `contests-web.service`, `127.0.0.1:8080` |
| Проверяющий процесс | `contests-worker.service` |
| Менеджер cgroups песочницы | `isolate.service` |
| Временные файлы проверки | `/var/local/lib/isolate`, tmpfs 256 МБ |
| Сайт Nginx | `/etc/nginx/sites-available/contests` |

На сервере 2 ГБ: веб-служба ограничена 384 МБ, worker — 256 МБ, ветка cgroups Isolate — 768 МБ. Решение по умолчанию получает 256 МБ, компиляция — 512 МБ. Проверки и компиляция идут по одной, с пониженным приоритетом CPU. Часть памяти остаётся ОС и Nginx.

```sh
systemctl status contests-web contests-worker isolate
journalctl -u contests-web -u contests-worker --since '10 minutes ago'
curl -f http://127.0.0.1:8080/healthz
```

Сайт показывает предупреждение, если worker не присылал heartbeat 30 секунд. Очередь переживает перезапуск. При старте worker повторно ставит незавершённые `RUNNING` в очередь. Файловая блокировка запрещает запуск двух worker на одной базе.

Текущая конфигурация рассчитана на HTTP внутри локальной сети (`http://192.168.10.5`). Перед доступом через интернет нужно настроить домен и HTTPS в Nginx; при проксировании HTTPS приложение автоматически ставит Secure на cookies. Не открывайте порт 8080 наружу — приложение доверяет заголовкам своего локального Nginx.

## Обновление

Сначала `make test vet build`. Затем скопировать новые `bin/contests` и `deploy/` в `/opt/contests/` и выполнить `bash /opt/contests/deploy/install.sh`. База и аккаунты сохраняются. Перед обновлением сделайте резервную копию.

## Резервная копия

В базе хранится всё постоянное содержимое. Копировать только `.db` при работающем приложении нельзя: новые данные могут находиться в WAL. Используйте SQLite backup:

```sh
install -d -m 0700 /var/backups/contests
sqlite3 /var/lib/contests/contests.db ".backup '/var/backups/contests/contests-backup.db'"
chmod 600 /var/backups/contests/contests-backup.db
sqlite3 /var/backups/contests/contests-backup.db 'PRAGMA integrity_check;'
```

Сохраните копию вне этого сервера. Для восстановления остановите обе службы, переместите текущую базу и её `-wal` / `-shm` в отдельный резервный каталог, скопируйте backup на место `.db`, установите владельца `contests:contests` и права `600`, затем запустите службы. Автоматический график резервного копирования в первой версии не настраивается.

## Тесты

`go test ./...` проверяет разграничение доступа, CSRF, вход, закрытые контесты, привязку версий, лимит отправок, валидацию архивов и сравнение ответов. Интеграционные проверки песочницы включаются только явно и требуют свободную песочницу 0:

```sh
# Остановить worker, чтобы тест не занял его песочницу.
systemctl stop contests-worker
runuser -u contests -- env RUN_ISOLATE_TESTS=1 \
  /opt/contests/bin/contests.test -test.run TestSandboxIntegration -test.v
systemctl start contests-worker
```

Тестовый бинарник собирается локально командой `CGO_ENABLED=0 go test -c -o bin/contests.test`. Проверяются Python/C++, неверный ответ, ошибка компиляции и выполнения, CPU/wall timeout, память, вывод и изоляция сети/файлов. Базу сайта эти тесты не изменяют.
