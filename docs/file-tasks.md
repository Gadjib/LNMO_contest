# Файловые задачи (.txt и .bin)

Формат задач версии 2 добавляет один входной и один выходной файл. Версия 1 и обычный stdin/stdout поддерживаются без изменений. Архив контеста остаётся версии 1; внутри него можно смешивать задачи версий 1 и 2.

Ученик сдаёт только исходный код. Учитель указывает имя в условии **и** в настройках ввода/вывода. Система не извлекает имена из текста. Программа запускается в `/box`, файлы открываются по относительному имени.

```yaml
format_version: 2
io:
  input:
    type: file
    name: source.bin
    content: binary
  output:
    type: file
    name: result.bin
    content: binary
checker:
  type: bytes
```

Остальные поля `problem.yaml` — как в [формате задачи](task-format.md).

- `type`: `stdio` (по умолчанию) или `file`.
- `name`: имя рабочего файла. Латинские буквы, цифры, `_`, `-`, расширение `.txt` или `.bin`; до 80 символов. Вход и выход должны иметь разные имена. Пути и служебные имена запрещены.
- `content`: `text` (по умолчанию, UTF-8) или `binary`. Тип задаётся явно, а не определяется расширением. Бинарный режим доступен только для файлов.
- Для бинарного ответа обязателен `checker.type: bytes`: точное сравнение байтов, без нормализации пробелов и переводов строк. Для текста доступны обычные `tokens`/`exact`; `bytes` также можно использовать для строгого сравнения текста.

Можно читать `.bin`, а ответ печатать в stdout; или читать `.txt` и создавать `.bin`. Для стандартного потока блок можно опустить либо написать `type: stdio` (без имени файла).

## Тесты

```yaml
tests:
  - id: "01"
    input_file: tests/01.bin
    answer_file: tests/01.answer.bin
    points: 100
```

Это пути **в архиве**, не имена файлов программы. Содержимое `tests/01.bin` будет помещено в `source.bin`, а содержимое созданного программой `result.bin` сравнивается с `tests/01.answer.bin`. Эталон никогда не помещается в песочницу.

Бинарные файлы в ZIP — настоящие байты, не HEX и не Base64. В базе они хранятся как Base64 внутри JSON, без потери нулевых байтов и значений 128–255. ZIP-экспорт восстанавливает исходные байты.

В редакторе сайта тест можно загрузить файлом. Для бинарного содержимого поле показывает HEX: например `00 ff 80`; допускаются пробелы и переводы строк между байтами. При смене типа содержимого загрузите тесты заново. Для текстового содержимого поле остаётся обычным текстом. Примеры в условии всегда текстовые: бинарные примеры записывайте в HEX с пояснением.

## Проверка и диагностика

Каждый тест запускается в новой песочнице. В файловом режиме ввода stdin пустой. В файловом режиме ответа stdout не считается ответом; сообщения об ошибках по-прежнему собираются из stderr.

Отсутствующий выходной файл, каталог или символическая ссылка вместо него дают WA с пояснением. Ошибка выполнения или превышение лимита сохраняют свой вердикт. Пустой созданный файл — допустимый ответ, отличный от отсутствующего файла. Несовпадение бинарных данных показывает позицию первого отличающегося байта (с 0), а несовпадение только длины — размеры.

Учитель видит текстовые файлы как текст, бинарные — как HEX-просмотр первых 4096 байт. Можно скачать ввод, эталон и сохранённую часть вывода. Вывод сохраняется в пределах 64 КБ; при обрезании есть отметка. Ученик видит только диагностику своего решения, без ссылок на скрытые данные тестов.

Лимиты: до 1 МБ на вход и эталон, 16 МБ тестовых данных на задачу, 20 МБ на архив. Файл результата ограничивается `limits.output_kb`; действуют также лимиты времени, памяти, открытых файлов и существующее ограниченное tmpfs-хранилище песочницы (256 МБ, 16384 inode, один worker).

## Тестовый контест

Команда `contests file-demo -db /путь/к/базе.db` создаёт **новый черновик** с четырьмя задачами, по пять тестов и 100 баллов на задачу:

1. Сумма из `numbers.txt` → `sum.txt`.
2. Сумма значений байтов `data.bin` → stdout.
3. Инверсия байтов `source.bin` → `result.bin`.
4. Числа из `values.txt` → однобайтовые значения в `packed.bin`.

Есть пустые файлы, нулевые байты, байты 128–255 и тест со всеми 256 значениями. Эталонные решения на Python и C++ проверяются `TestFileIOIntegration` на сервере с Isolate. Этот тест требует остановленного рабочего проверяющего процесса, поскольку использует тот же box 0.
