# Формат олимпиадной задачи · версия 1

Задача — программа, которая читает стандартный ввод (`stdin`) и пишет ответ в стандартный вывод (`stdout`). Каждый тест запускается в новой песочнице. Доступа к сети, базе сайта и чужим решениям нет. Интерактивные задачи, файловый ввод/вывод и пользовательские программы проверки в версии 1 не поддерживаются.

Учитель создаёт задачу через форму на сайте либо загружает ZIP-архив. Оба способа создают одинаковую запись в базе. При редактировании сохраняется новая неизменяемая версия условия и тестов. Отправка всегда ссылается на конкретную версию.

## Архив

```text
sum.zip
├── problem.yaml
└── tests/
    ├── 01.in
    ├── 01.out
    ├── 02.in
    └── 02.out
```

`problem.yaml` должен находиться в корне архива. Все текстовые файлы — UTF-8. Пути относительные, с `/`; абсолютные пути, `..`, символьные ссылки и повторяющиеся имена запрещены. Архив читается в памяти, на диск не распаковывается.

Максимум: 20 МБ для ZIP и его распакованного содержимого, 225 записей архива, 1 МБ для каждого файла, 16 МБ суммарно для входных данных и ответов тестов. Для больших наборов используйте ZIP-импорт; обычные формы ограничены размером HTTP-запроса.

```yaml
format_version: 1
code: sum
title: "Сумма двух чисел"

statement: |
  Даны два целых числа. Найдите их сумму.

input_format: |
  Одна строка содержит целые числа a и b.
  -10^9 ≤ a, b ≤ 10^9.

output_format: |
  Выведите одно целое число — сумму a и b.

notes: ""

limits:
  time_ms: 1000
  memory_mb: 256
  output_kb: 1024

allowed_languages:
  - python3
  - cpp17

checker:
  type: tokens

scoring:
  type: sum
  max_score: 100

examples:
  - input: |
      2 3
    output: |
      5
    explanation: "2 + 3 = 5."

tests:
  - id: "01"
    input_file: tests/01.in
    answer_file: tests/01.out
    points: 50
  - id: "02"
    input_file: tests/02.in
    answer_file: tests/02.out
    points: 50
```

## Поля

| Поле | Смысл и ограничения |
|---|---|
| `format_version` | Обязательно `1`. Неизвестные поля YAML отклоняются. |
| `code` | Уникальный внутри контеста код: 1–40 латинских букв, цифр, `_`, `-`. Первый символ — буква или цифра. |
| `title` | Обязательное название, до 300 байт UTF-8. |
| `statement` | Обязательное условие, до 100 000 байт. Поддерживается Markdown, опасный HTML удаляется. |
| `input_format`, `output_format` | Обязательные описания ввода и вывода, Markdown. |
| `notes` | Необязательное примечание, Markdown. |
| `limits.time_ms` | CPU-время на один тест, 100–10 000 мс. |
| `limits.memory_mb` | Память на один тест, 16–512 МБ. Учитывается cgroup, включая часть файлового кеша. |
| `limits.output_kb` | Максимальный размер файла вывода, 1–1024 КБ. Достижение предела stdout считается превышением вывода. |
| `allowed_languages` | Один или оба языка: `python3`, `cpp17`; без повторов. |
| `checker.type` | `tokens`, `exact` либо встроенный чекер `evacuation` / `garden_beds`. |
| `scoring.type` | В версии 1 только `sum`. |
| `scoring.max_score` | Целое число 1–10 000. |
| `examples` | До 20 публичных примеров, каждый до 100 000 байт вместе с пояснением. Можно оставить пустым списком. |
| `tests` | От 1 до 100 скрытых тестов. |
| `tests[].id` | Уникальный идентификатор по тем же правилам, что `code`. Числовые ID записывайте в кавычках. |
| `tests[].input_file` | Путь к файлу входных данных внутри ZIP. |
| `tests[].answer_file` | Путь к файлу правильного ответа внутри ZIP. |
| `tests[].points` | Целый вес теста от 0 до 10 000. Сумма весов равна `max_score`. |

В форме на сайте вместо путей файлов есть текстовые поля входа и ответа. Для массовой загрузки файлов используется ZIP. Экспорт автоматически создаёт `problem.yaml` и файлы тестов; внутренние номера версий и принадлежность контесту в архив не включаются.

## Картинки в условии

В редакторе задачи выберите файл в поле «Вставить картинку» под описанием. Markdown-ссылка вставится в описание на месте курсора. Замените текст «Описание картинки» подходящей подписью и сохраните задачу. Ссылку можно перенести в формат ввода/вывода, примечание или пояснение к примеру.

Поддерживаются PNG и JPEG: до 1 МБ на файл, размеры до 4096 × 4096 пикселей. На задачу — не больше 20 картинок общим размером до 3 МБ; общий лимит ZIP остаётся 20 МБ. SVG не принимается. Загрузка доступна только учителям и администраторам, до 60 файлов в час на аккаунт.

В ZIP положите изображения в каталог `assets/` и ссылайтесь на них из Markdown:

```yaml
statement: |
  На рисунке показан граф.

  ![Граф](assets/graph.png)
```

Файл `assets/graph.png` должен присутствовать в архиве. Используйте относительные пути без пробелов. При импорте картинки сохраняются в базе, ссылки заменяются внутренними адресами. Экспорт ZIP включает картинки и восстанавливает переносимые ссылки на `assets/`. Старые архивы без картинок остаются совместимыми; `format_version` не меняется.

Картинки хранятся в SQLite отдельно от текста версий и включаются в резервную копию базы. Удаление ссылки из новой версии не удаляет изображение старой версии. Ученики могут открыть изображение только после его сохранения в задаче опубликованного, уже начавшегося контеста. До этого оно доступно только учителям и администраторам. Внешние сайты для размещения картинок не нужны.

## Сравнение и баллы

`tokens` разбивает ответ на последовательности непробельных символов и сравнивает их по порядку. Количество пробелов, пустые строки и завершающий перевод строки не важны. Числа не преобразуются: `1`, `01` и `1.0` — разные ответы. Приближённого сравнения вещественных чисел нет.

`exact` сравнивает текст после замены CRLF и CR на LF. Остальные пробелы и завершающий перевод строки значимы. Поэтому сохраняйте нужный перевод строки в `.out`; YAML `|` сохраняет его, а `|-` удаляет.

`evacuation` проверяет план эвакуации для сетки из входных чисел `n m r1 c1 r2 c2`: две лестницы, допустимые стрелки, отсутствие циклов и минимальность маршрутов. `garden_beds` проверяет выбор четырёх имеющихся досок, размер уголка и его совпадение с оптимумом из эталонного `.out`.

За пройденный тест начисляется его вес, за непройденный — 0. Все тесты проверяются, даже если первый не пройден. `AC` означает прохождение всех тестов, включая тесты с нулевым весом. При нескольких ошибках итоговый статус соответствует первой по порядку; подробности видны по каждому тесту.

В таблице контеста учитывается максимальный балл среди завершённых попыток ученика по задаче. Отправки в очереди и системные ошибки не учитываются. После первой отправки максимальный балл задачи менять нельзя, чтобы результаты разных версий оставались сопоставимыми.

Кнопка повторной проверки использует **исходную версию** тестов и обновляет результат этой попытки. Новая версия задачи применяется только к новым отправкам. Если необходимо полностью изменить критерии уже проведённого контеста, лучше создать новый контест; массового пересчёта на новых тестах в первой версии нет.

## Языки и ограничения запуска

- Python: системный `python3` Debian, запуск `python3 -I -B /box/main.py`. Доступна стандартная библиотека, сторонние пакеты не устанавливаются.
- C++: `g++ -std=c++17 -O2 -pipe`, отдельная компиляция в песочнице. Лимиты компиляции: 10 секунд CPU, 32 секунды реального времени, 512 МБ памяти, до 16 процессов, до 16 МБ на файл.
- Размер исходника — до 64 КБ. Один процесс при выполнении решения; дополнительные процессы и потоки запрещены.
- Реальное время теста дополнительно ограничено формулой `3 × CPU-лимит + 2 секунды`, чтобы остановить спящую программу.
- Одновременно проверяется одна отправка; её тесты выполняются последовательно. До 3 незавершённых отправок на ученика, интервал между отправками — минимум 5 секунд.
- Для каждой проверки временная файловая система ограничена общим размером 256 МБ. После теста она очищается. Эталонный ответ в песочницу не передаётся.

Для Python учитывайте время запуска интерпретатора и память стандартной библиотеки: практичный стартовый лимит — 1000 мс и 256 МБ.

## Результаты

| Код | Значение |
|---|---|
| `QUEUED` | Ожидает проверки. |
| `RUNNING` | Компилируется или проходит тесты. |
| `AC` | Все тесты пройдены. |
| `WA` | Ответ отличается от эталона. |
| `TLE` | Превышено CPU-время или реальное время. |
| `MLE` | Программа остановлена ограничением памяти cgroup. |
| `RE` | Ненулевой код возврата, сигнал или некорректные выходные файлы. |
| `CE` | Компиляция не завершилась успешно, включая превышение её лимитов. |
| `OLE` | Достигнут предел stdout либо получен сигнал превышения размера файла. |
| `JE` | Ошибка самой инфраструктуры проверки; баллы не учитываются. |

Ученик видит код своего решения, баллы, статусы тестов, время, память и сообщение компилятора. Он не получает скрытые входы, эталоны, stdout и stderr тестов. В карточке отправки учителю доступны входные данные, вывод ученика, ожидаемый ответ и диагностика каждого теста. Вход и эталон берутся из версии задачи, закреплённой за отправкой. Ошибочные тесты раскрыты сразу, успешные — по нажатию «Данные теста». Новые проверки сохраняют до 64 КБ stdout и 4 КБ stderr на тест. У старых отправок сохраняется прежний предел stdout (4 КБ); получить больший фрагмент можно повторной проверкой. Ошибка выделения памяти, которую программа сама обработала или завершила обычным исключением, может классифицироваться как `RE`, если cgroup не зафиксировал OOM.

Готовый пример находится в `examples/sum/`. Создать архив из этого каталога: `zip -r ../../sum.zip problem.yaml tests`.
